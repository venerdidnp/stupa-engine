# Plan

A from-scratch 3D renderer (Python + NumPy) and a Three.js viewer for a
low-poly textured temple. This file is the build plan: what to build, in what
order, and how to know each step is correct.

## 0. Ground rules

- **Pipeline code is NumPy only.** No OpenGL, no 3D libraries, no rendering
  libraries. Pillow is allowed only to convert images, never to render.
- **Conventions are pinned** at the top of `transforms.py` and never mixed:
  - column vectors, `p' = M @ p`, chain "A then B" is `B @ A @ p`
  - right-handed, camera looks down **-z**
  - NDC is `[-1, 1]^3`, near plane at `z = -1`
  - front face is CCW, cull back faces
  - UV origin bottom-left (flip `v` once, in the loader)
  - all angle parameters end in `_deg`, converted to radians at the boundary
- **Deterministic assets.** The model and texture are generated by script. No
  binary assets are committed.
- **Every module has a self-check** in `tests.py` with known numbers.
- Code is fully commented: what each block does and why, not just what.

## 1. Repo layout

```
transforms.py     4x4 matrices, perspective, lookAt, viewport
objio.py          minimal OBJ loader (v / vt / f)
ppm_io.py         read/write P6 PPM
make_model.py     generates the stepped temple .obj + UVs + texture
raster3d.py       MVP, near clip, w-divide, z-buffer raster, texturing, Lambert
raytrace.py       pinhole rays + Moller-Trumbore, same shading
worked_example.py follows one vertex through every space
broken_scene.py   reproduces bugs (inside-out, z-fight, stretched) + fixes
metrics.py        PSNR + simple global SSIM
compare.py        compares two renders, writes a diff image
tests.py          all numeric checks
data/             generated model + texture
out/              rendered frames, depth maps, diffs
web/              Three.js viewer (index.html, viewer.js)
requirements.txt  pinned versions
```

## 2. Phases

Each phase ends with a check. Do not start the next phase until it passes.

### Phase 1: Math core (`transforms.py`, `tests.py`)

- `translate`, `scale`, `rot_x`, `rot_y`, `rot_z`
- `perspective(fovy_deg, aspect, near, far)`
- `look_at(eye, target, up)` built as the inverse of the camera pose
  (`R^T` and `-R^T c`)
- `viewport(ndc, w, h)` with y flipped (screen y points down)
- `project(P, V, M, verts)` returns clip and NDC

**Check (reference values):**

| Case                                                             | Expected                  |
| ---------------------------------------------------------------- | ------------------------- |
| `(2,3,4)`, translate `(1,0,-1)` then `rot_y(90)`                 | `(3, 3, -3)`              |
| perspective divide of that point, `d = 2`                        | `(2, 2)`                  |
| same point, `rot_y(90)` first then translate                     | `(5, 3, -3)`              |
| camera moved `+1` on x vs model moved `-1` on x, point `(5,0,0)` | both give `(4, 0, 0)`     |
| `perspective` with `n=1, f=9`: `z=-1`, `z=-9`, `z=-3`            | NDC z = `-1`, `+1`, `0.5` |
| coefficients for `n=1, f=9`                                      | `A = -1.25`, `B = -2.25`  |

### Phase 2: I/O and model (`ppm_io.py`, `objio.py`, `make_model.py`)

- PPM reader/writer.
- OBJ loader: `v`, `vt`, `f` (triangulate quads; handle `v/vt` and `v/vt/vn`).
  Enforce CCW winding and flip `v` here, once.
- `make_model.py`: stepped temple, about 15 stacked boxes, planar UVs, plus a
  procedural 256x256 sandstone texture (`data/relief.ppm`).
  Target: 180 triangles, 120 vertices.

**Check:** loader returns the expected counts; texture is 256x256.

### Phase 3: Rasterizer (`raster3d.py`), built in small steps

Render the temple after each step so regressions are visible.

1. Project vertices, draw wireframe or flat triangles (no depth).
2. Barycentric triangle fill with a bounding box.
3. Z-buffer (init `+inf`, interpolate NDC z linearly with barycentric weights).
4. Near-plane clipping in clip space (before the w-divide).
5. Back-face culling.
6. Lambert shading, one directional light.
7. Texture mapping with perspective-correct UV (interpolate `u/w`, `v/w`,
   `1/w`, then divide per pixel).
8. Bilinear sampling.
9. Mipmaps (4-level pyramid, gamma-correct box downscale, pick level by
   texel/pixel ratio).

Outputs: `out/temple_raster.ppm` and `out/temple_depth.ppm`.

**Check (reference values):**

| Case                                                           | Expected                    |
| -------------------------------------------------------------- | --------------------------- |
| barycentric `(0.25, 0.25, 0.5)` with depths `0.20/0.50/0.90`   | `0.625`                     |
| floor edge, `w_L = 1`, `w_R = 9`, `u: 0 -> 1`, screen midpoint | naive `0.5`, correct `0.1`  |
| two overlapping triangles at depth ~0.3 and ~0.7               | back never wins the overlap |

### Phase 4: Ray tracer (`raytrace.py`)

One pinhole ray per pixel, Moller-Trumbore against every triangle, nearest
hit, same texture and same light as the rasterizer.

**Check:** `compare.py` raster vs ray trace gives PSNR above 60 dB, with any
differences only on silhouette pixels.

### Phase 5: Metrics and comparison (`metrics.py`, `compare.py`)

PSNR, a simple global SSIM, mean and max absolute difference, and an amplified
difference image.

### Phase 6: Worked example (`worked_example.py`)

Trace one vertex through object, world, view, clip, NDC, screen and print
every intermediate value.

**Check (reference run):** point `(2,3,4)`, model = `rot_y(90) @ translate(1,0,-1)`,
camera at `(0,0,8)` looking at the origin, `perspective(60, 1, 1, 50)`, 800x600:

```
world  = (3, 3, -3, 1)
eye    = (3, 3, -11, 1)
clip   = (5.196, 5.196, 9.408, 11)
ndc    = (0.472, 0.472, 0.855)
screen = (589, 158), depth 0.928
```

### Phase 7: Broken scenes (`broken_scene.py`)

Three flags, each reproducing a bug with evidence and a fix:

| Flag               | Cause                   | Evidence                             | Fix                      |
| ------------------ | ----------------------- | ------------------------------------ | ------------------------ |
| `--bug inside-out` | wrong winding / culling | render, SSIM vs reference            | CCW + cull back          |
| `--bug zfight`     | `near = 1e-3`           | depth histogram, flicker pixel count | raise near, or reverse-Z |
| `--bug stretched`  | swapped matrix order    | printed matrices, SSIM               | correct `P @ V @ M`      |

### Phase 8: Web viewer (`web/`)

- Three.js, OBJ loader, same texture, `OrbitControls`, one directional light,
  sRGB output.
- Fixed canvas size 512x512, `setPixelRatio(1)`, and a button that exports the
  canvas to PPM so `compare.py` can diff it against the NumPy render.
- Expected: about 30 dB PSNR vs the NumPy frame, with differences on edges
  (MSAA) and specular highlights, not in the interior.

### Phase 9: Ship

- Deploy `web/` to GitHub Pages.
- Fresh-clone test: `pip install -r requirements.txt`, `python make_model.py`,
  `python tests.py` (all green), `npx serve web`.
- Fill in "Tested on" in the README.

## 3. Optional extras (only after everything above works)

- Reverse-Z with a float depth buffer
- Sutherland-Hodgman clipping against all six frustum planes
- Inverse-transpose normal matrix for non-uniform scale
- Hard shadows in both renderers

## 4. Definition of done

- `python tests.py` prints all checks passed
- raster vs ray trace: PSNR above 60 dB
- raster vs WebGL: about 30 dB, differences only on edges and highlights
- three broken scenes reproduce and each has a verified fix
- live demo orbits the textured temple at an interactive frame rate
- a fresh clone works end to end
